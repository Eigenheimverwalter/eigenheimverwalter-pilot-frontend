# Basic referral capacity: backend preparation

The existing public confirmation route now uses one extracted mutation function.
With `PILOT_PARTNER_ONBOARDING_ENABLED=true`, Basic partners retain three distinct
confirmed own properties. Further confirmations remain stored with
`activationStatus=upgrade_required`; equipment assignments remain `pending_upgrade`
and confer no property access. Existing assignments are not removed.

Premium own referrals are independent of protected licence postal codes. EHV lead
allocation is unchanged. With the gate disabled, the legacy flow remains intact.

Runtime persistence retains the revision compare-and-swap transaction. Concurrent
confirmations return 409 on conflict and must be retried against current capacity.

Validation: 288 Node tests pass, including the actual public HTTP handler under
concurrent confirmations, role scoping, tipsters, Premium geography and gate-off
compatibility.

Not yet released: the gate remains closed. The visible upgrade dialog, verified
Stripe activation and release of pending assignments are subsequent work. No real
